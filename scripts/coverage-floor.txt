# Statement coverage floors, one package per line.
#
# The rule is "do not go backwards", not "reach a number". A floor is
# raised by adding tests; it is never lowered to make a build pass, and
# `go run ./scripts/check-coverage -update` refuses to lower one. Lowering
# a floor is an explicit edit to this file, which is the review it forces.
#
# A floor is a whole percentage point, and the gate allows one point of slack
# below it. Statement coverage moves by a few tenths between runs of the same
# commit when a branch is only reached under a schedule the test cannot pin -
# internal/tool alternates between 82.1% and 82.3% for that reason - and a
# gate that fires on that teaches people to re-run it. A real loss costs
# several points and is still caught.
#
# Every package that reports coverage is listed, including the ones that
# report none. The module root, the command entry points and the four dialect
# packages exist to be called rather than to be tested - each dialect package is
# thirteen lines of wrapping around webnative - so a floor of 0 for them says
# that rather than pretending they are measured against a target. They are still
# compared: a package that reported coverage before and reports none now falls
# below the floor recorded for it and fails the gate.
